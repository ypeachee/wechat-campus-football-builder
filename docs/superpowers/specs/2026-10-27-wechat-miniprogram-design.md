# 校园足球微信小程序设计

**日期：** 2026-10-27  
**状态：** 已确认技术方向，等待书面 spec 审阅  
**后端基线：** `main` 分支校园足球 API MVP  
**范围：** 微信小程序公开端与管理端 V1

## 1. 目标

在现有 Spring Boot API 之上实现一个可直接在微信开发者工具运行的小程序，满足三类核心场景：

1. 浏览球队、球员、赛程和比赛详情。
2. 查看积分榜、射手榜、助攻榜和出场榜。
3. 管理员和球队管理员在各自权限范围内维护数据。

小程序不复制后端业务规则。权限、锁定、统计口径和审计仍以后端为唯一可信来源。

## 2. 技术选型

- 原生微信小程序
- TypeScript
- TDesign MiniProgram
- `miniprogram-api-typings`
- Vitest 用于纯 TypeScript 单元测试
- 微信开发者工具负责编译、预览、真机调试和 npm 构建
- Node.js 20 或更高版本

不使用 uni-app、Taro 或跨端框架。当前目标只有微信，原生方案可以减少构建层和平台适配成本。

不直接复制第三方项目的业务代码、视觉资产或未明确授权的资源。

## 5. 页面设计

### 5.1 首页

展示当前赛季的核心信息：

- 顶部当前赛季与轮次摘要
- 最近/下一场比赛卡片
- 积分榜前 3
- 射手榜前 3
- 快捷入口：查看完整赛程、查看榜单、查看球队

无赛季数据时显示引导空状态。公开访问不要求登录。

### 5.2 赛程

- 赛季选择器
- 状态筛选：全部、未开始、进行中、已完赛
- 比赛列表卡片：主客队、比分、时间、状态
- 下拉刷新和触底加载预留
- 点击进入比赛详情

公开接口不返回 `DRAFT` 比赛。

### 5.3 比赛详情

- 双方球队、比分、比赛状态、时间和场地
- 事件时间线：进球、助攻、乌龙、红牌、黄牌
- 出场名单：首发/替补和出场分钟
- 进球事件显示进球球员与助攻球员关系
- 管理入口根据角色和后端权限显示，不根据前端猜测授权

### 5.4 球队

- 球队卡片列表
- 球队详情：队名、教练、主场
- 球员列表：号码、姓名、位置
- 点击球员进入球员详情

### 5.5 球员详情

- 姓名、号码、位置、所属球队
- 基本信息只读展示
- 球员统计若后端未提供单球员聚合接口，V1 不自行拼接全量榜单；只展示榜单入口，避免制造错误数据

### 5.6 榜单

使用顶部四项分段：

1. 积分榜
2. 射手榜
3. 助攻榜
4. 出场榜

统一赛季筛选。积分榜展示场次、胜平负、进失球、净胜球和积分；球员榜展示排名、球员、球队和统计值。

### 5.7 我的

未登录：

- 微信登录按钮
- 公开功能说明

已登录：

- 当前角色
- 可管理球队
- 管理入口
- 退出登录

角色显示：

- `ADMIN`：联赛管理员
- `TEAM_MANAGER`：球队管理员
- `VIEWER`：普通用户

## 6. 管理端

### 6.1 管理首页

根据角色展示入口：

- 管理员：赛季、赛程、球队授权、审计日志、球队资料、比赛数据
- 球队管理员：本队资料、本队球员、比赛数据
- 普通用户：不显示管理入口

前端入口只用于导航，真正的权限检查仍在后端。

### 6.2 球队资料与球员

- 管理员可选择任意球队
- 球队管理员只能选择自己管理的球队
- 编辑队名、简称、教练、主场、队徽 URL
- 球员列表支持新增、编辑、停用
- 球衣号码冲突显示后端 `CONFLICT` 错误
- 管理员可切换球队状态；球队管理员不能修改球队状态

### 6.3 管理员赛季

- 创建赛季：名称、开始日期、结束日期、状态
- 赛季列表，包括 `DRAFT` 赛季
- 添加/移除参赛球队
- 已被比赛引用的球队移除失败时展示明确提示

### 6.4 管理员赛程

- 创建比赛：赛季、轮次、主队、客队、时间、场地
- 修改赛程信息
- 状态流转：草稿、未开始、进行中、取消
- 完赛：录入官方比分，提交后比赛自动锁定
- 解锁后允许继续维护数据
- 锁定状态下写操作展示 `FIXTURE_LOCKED`

### 6.5 比赛数据录入

管理员和球队管理员共用页面，但可选球队范围不同：

- 出场记录：球员、首发、分钟数
- 比赛事件：进球、乌龙、黄牌、红牌
- 进球事件可选助攻球员
- 球队管理员只能提交本队数据
- 锁定、比赛状态和球队范围错误全部由后端校验

### 6.6 管理员球队授权

- 按球队查看当前管理员
- 授权用户需输入用户 ID 或从后端未来提供的用户列表选择
- V1 后端没有用户搜索接口时，使用用户 ID 输入并显示明确提示
- 支持撤销授权

### 6.7 审计日志

- 管理员查看全部日志
- 球队管理员查看本队及参赛比赛日志
- 展示时间、操作人、动作、实体类型、实体 ID
- JSON 前后值使用折叠详情展示

## 7. 视觉方向

关键词：校园球场、清爽、数据优先。

色板：

- 球场深绿：`#0B6B4B`
- 荧光草绿：`#B7F34A`
- 墨色：`#14201D`
- 沙色背景：`#F4F1E8`
- 白色卡片：`#FFFFFF`
- 警示红：`#C7392F`
- 信息蓝：`#2463A8`

设计规则：

- 白底/沙色底为主，深绿用于标题、选中态和关键按钮
- 比分和榜单数字使用更大字号与高字重
- 卡片圆角统一为 `20rpx`
- 触控区域不小于 `88rpx`
- 不使用复杂 3D、玻璃拟态或大面积渐变
- V1 只做浅色主题
- 使用 TDesign 组件，但通过主题变量覆盖品牌色

## 9. 网络与认证

### 9.1 API 地址

`config/env.ts` 根据微信环境版本提供：

- `develop`：本地或测试 API
- `trial`：体验环境 API
- `release`：生产 API

生产 API 必须使用 HTTPS，并加入微信小程序 request 合法域名。

### 9.2 HTTP 封装

`services/http.ts` 统一处理：

- `wx.request` Promise 化
- 基础 URL
- `Authorization: Bearer <token>`
- 10 秒超时
- JSON 请求与响应
- 401 清理 session 并跳转登录
- 403、404、409 和后端错误码转成可展示提示
- 显示或记录 `requestId`，便于排查

页面不得直接调用 `wx.request`。

### 9.3 登录

1. 用户点击登录。
2. 调用 `wx.login()` 获取 code。
3. 调用 `POST /api/v1/auth/wechat-login`。
4. 保存 token、用户 ID、昵称、角色和可管理球队。
5. 调用 `GET /api/v1/me` 刷新角色与球队权限。
6. 成功后返回来源页面或“我的”。

小程序端不得保存 `appSecret`，也不得自行判断球队授权。

### 9.4 会话

- token 存储在 `wx.setStorageSync`
- 启动时恢复会话
- token 过期或用户被停用时清理缓存并提示重新登录
- 退出登录只清理本地会话，不调用后端注销接口

## 10. 状态与数据流

V1 使用轻量本地状态，不引入 Redux、MobX 或 Pinia：

- `state/session.ts`：token、用户、角色、managedTeamIds
- `state/season.ts`：当前选中赛季 ID，存储在本地
- 页面内 `data`：列表、表单、loading、error
- 服务层负责 API 映射，页面负责展示和交互

公共页面不依赖登录状态。管理页面在 `onShow` 时重新校验角色和权限，防止从缓存进入过期页面。

## 11. 交互与错误处理

- 首次加载使用骨架屏或 `t-loading`
- 列表为空显示 `empty-state`
- 下拉刷新用于所有公开列表页
- 提交中禁用按钮，防止重复提交
- 表单错误显示在字段附近，并保留用户输入
- 网络错误提供“重试”
- 403 显示“没有权限”
- `FIXTURE_LOCKED` 显示“比赛已锁定，请管理员先解锁”
- 404 显示资源不存在或已下架
- 409 显示后端提供的冲突原因
- 不把原始异常或堆栈展示给用户

## 12. 测试策略

### 12.1 自动化测试

- `tsc --noEmit`：TypeScript 类型检查
- Vitest：HTTP 错误映射、session 存取、角色判断、日期与状态格式化
- 使用 mock `wx` 对象，不依赖真实微信环境

### 12.2 开发者工具验收

- 公开页面在未登录状态下可访问
- 登录后角色和管理入口正确
- 管理员完整流程可操作
- 球队管理员只能操作本队
- 锁定比赛写操作显示明确错误
- 赛季切换后赛程和榜单同步刷新
- 从后台恢复或重新进入页面时不会丢失当前赛季

### 12.3 真机验收

- iOS 和 Android 微信各至少验证一次
- 安全区、底部 Tab、弹层和键盘不遮挡表单
- 弱网下显示加载或重试状态

## 13. 非目标

V1 不包含：

- 多端发布（H5/App）
- 微信支付
- 图片上传和对象存储
- 评论、点赞和社交动态
- 直播或视频
- 推送订阅消息
- 球员单场热区、跑动距离等高级统计
- 离线写入和冲突合并
- 多语言

## 14. 验收标准

### 14.1 公开端

- 未登录用户可浏览赛季、球队、球员、赛程、比赛详情和四类榜单。
- `DRAFT` 赛季和比赛不会出现在公开页面。
- 赛季切换后，赛程和榜单请求使用对应 `seasonId`。
- 比赛详情正确显示事件和出场记录。

### 14.2 登录与权限

- `wx.login` 可以完成后端登录并保存会话。
- 角色变化后重新进入管理页面能刷新权限。
- 普通用户看不到管理入口。
- 球队管理员只看到自己球队的管理选项。
- 管理员可以访问全部管理入口。

### 14.3 管理端

- 管理员可创建赛季、添加球队、创建比赛、切换状态、录入比分、完赛和锁定。
- 管理员可创建/编辑球队和球员、授权/撤销球队管理员。
- 球队管理员可编辑本队资料和球员，不能修改球队状态。
- 球队管理员可维护本队出场和事件，不能操作其他球队。
- 锁定比赛的所有非解锁写操作都显示 `FIXTURE_LOCKED`。
- 审计日志按角色范围显示。

### 14.4 工程质量

- `npm run typecheck` 通过。
- `npm test` 通过。
- `npm run build` 或等价构建检查通过。
- 微信开发者工具无编译错误。
- 所有页面具备 loading、空状态和错误态。

## 15. 实施前必须确认

- 微信小程序 `appId` 和 `appSecret` 由用户提供；后者只配置在后端。
- 生产 API 域名可配置 HTTPS 并在微信后台加入合法域名。
- 开发者工具中需要执行 npm 构建，生成 TDesign 组件依赖。
