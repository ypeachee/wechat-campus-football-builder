# 授权管理员全局管理权限设计

**日期：** 2026-10-28  
**状态：** 已确认方向，等待规格复核  
**影响范围：** Spring Security、后端授权服务、管理端 API、小程序管理台、角色文案、集成测试

## 1. 目标

将现有 `TEAM_MANAGER` 从“只能管理被授权球队的球队管理员”升级为全局“授权管理员”。

授权管理员可以使用除以下两类功能外的全部管理能力：

- 审计日志
- 评分审核与敏感词管理

`VIEWER` 仍为普通只读用户。`ADMIN` 仍为超级管理员，拥有全部权限。

## 2. 权限矩阵

| 功能 | ADMIN | TEAM_MANAGER（授权管理员） | VIEWER |
|---|---:|---:|---:|
| 浏览公开内容 | 可以 | 可以 | 可以 |
| 普通评分、主裁评分、举报 | 可以 | 可以 | 需登录后评分 |
| 球队、球员新增与编辑 | 可以 | 可以 | 不可以 |
| 球队状态修改 | 可以 | 可以 | 不可以 |
| 球队管理员授权/撤销 | 可以 | 可以 | 不可以 |
| 赛事、赛季、阶段、小组管理 | 可以 | 可以 | 不可以 |
| 赛程、状态、比分、锁定/解锁 | 可以 | 可以 | 不可以 |
| 出场、阵容、事件录入 | 可以 | 可以 | 不可以 |
| 淘汰赛、种子、晋级、点球 | 可以 | 可以 | 不可以 |
| 审计日志 | 可以 | 不可以 | 不可以 |
| 评分审核 | 可以 | 不可以 | 不可以 |
| 敏感词管理 | 可以 | 不可以 | 不可以 |

## 3. 角色存在条件

继续保留现有 `team_manager` 关联表：

- 用户至少有一条球队授权时，保持 `TEAM_MANAGER` 角色。
- 授权管理员可以管理全部球队和赛事，但球队关联仍是角色存在条件。
- 最后一条球队授权被撤销后，非 `ADMIN` 用户自动降为 `VIEWER`。
- 已存在的 `TEAM_MANAGER` 账号在部署后立即获得新权限，不需要数据库迁移。

不新增角色，不新增数据库表。

## 4. 后端授权设计

### 4.1 SecurityConfig

匹配顺序必须保证管理员专属接口先于通用管理接口：

```text
/api/v1/admin/ratings/**             -> ADMIN
/api/v1/admin/sensitive-terms/**     -> ADMIN
/api/v1/manage/audit-logs            -> ADMIN
/api/v1/admin/**                     -> ADMIN, TEAM_MANAGER
/api/v1/manage/**                    -> ADMIN, TEAM_MANAGER
```

### 4.2 AuthorizationService

新增明确语义：

- `requireManagementAccess(userId)`：允许 `ADMIN` 和 `TEAM_MANAGER`。
- `isManagementAdmin(userId)`：判断是否拥有全局管理权限。
- 保留 `requireAdmin(userId)`：只用于审计、评分审核和敏感词。

不要让评分审核或审计服务误用全局管理判断。

### 4.3 服务层替换

以下服务中的管理员校验改为 `requireManagementAccess`：

- `TeamService` 的球队创建与全局编辑
- `PlayerService` 涉及的全局球队球员管理
- `TeamManagerService` 的授权与撤销
- `CompetitionService`
- `SeasonService`
- `StageService`
- `GroupService`
- `FixtureService`
- `BracketService`
- 其他仅调用 `requireAdmin` 的赛事管理服务

以下服务继续使用 `requireAdmin`：

- `AuditQueryService`
- `RatingModerationService`
- `SensitiveTermService`

### 4.4 比赛数据与阵容

`AppearanceService` 和 `EventService` 对 `TEAM_MANAGER` 采用与 `ADMIN` 相同的全局写权限：

- 可以维护任意参赛球队。
- 比赛状态写窗口与 `ADMIN` 相同：`SCHEDULED`、`LIVE`、未锁定的 `FINISHED`。
- 仍必须验证球队属于本场比赛。
- 锁定比赛仍拒绝写入。
- 跨队球员、重复阵容、事件球员删除等数据约束不变。

### 4.5 审计行为

授权管理员执行管理操作时：

- 仍写入审计日志。
- 不能读取审计日志。
- 审计记录的 actor、team 和 before/after 行为保持不变。

## 5. 小程序管理台设计

### 5.1 角色文案

`TEAM_MANAGER` 显示为“授权管理员”，不再显示“球队管理员”。

### 5.2 管理首页

`ADMIN` 与 `TEAM_MANAGER` 都显示全局管理入口：

- 赛季管理
- 赛程管理
- 球队授权
- 比赛数据
- 赛事层级
- 淘汰赛
- 球队资料与新建球队

仅 `ADMIN` 显示：

- 审计日志
- 评分审核

`TEAM_MANAGER` 不再显示“只显示你被授权的球队”或只能录入本队比赛的管理界面。

### 5.3 页面门禁

允许 `ADMIN` 和 `TEAM_MANAGER`：

- 赛事层级
- 赛季管理
- 赛程管理
- 球队授权
- 淘汰赛
- 球队资料
- 比赛数据

仅允许 `ADMIN`：

- 审计日志
- 评分审核与敏感词

### 5.4 球队与比赛页面

- 球队管理页对授权管理员使用全局球队/球员 API。
- 授权管理员可以新建球队并修改球队状态。
- 比赛数据页对授权管理员加载全部赛季、球队和比赛。
- 前端门禁只用于导航；最终权限仍由后端判断。

## 6. 错误处理

- 授权管理员访问审计或审核接口返回 `403 FORBIDDEN`。
- `VIEWER` 访问任一管理接口返回 `403`，未登录返回 `401`。
- 页面收到 `403` 时显示“没有权限”，不得继续展示管理操作。
- 角色被撤销后重新进入管理页必须刷新为 `VIEWER` 并退出管理入口。

## 7. 测试

### 后端集成测试

至少覆盖：

1. 授权管理员可以创建球队、编辑任意球队。
2. 授权管理员可以创建赛事、赛季、阶段和小组。
3. 授权管理员可以创建和修改任意比赛、比分和锁定状态。
4. 授权管理员可以维护任意参赛球队的阵容与事件，包括 `SCHEDULED` 比赛。
5. 授权管理员可以授权和撤销球队管理员。
6. 授权管理员可以管理淘汰赛和晋级。
7. 授权管理员访问审计日志返回 `403`。
8. 授权管理员访问评分审核和敏感词接口返回 `403`。
9. 普通用户访问管理接口返回 `403`。
10. 最后一条球队授权撤销后角色降为 `VIEWER`，后续管理请求返回 `403`。

### 前端测试

- `TEAM_MANAGER` 的管理入口包含除审计和评分审核外的全部入口。
- `TEAM_MANAGER` 不显示审计和评分审核。
- `ADMIN` 显示全部入口。
- `VIEWER` 不显示管理入口。
- 授权管理员在球队和比赛页面使用全局管理服务。
- 角色文案显示“授权管理员”。

## 8. 非目标

- 不新增 `AUTHORIZED_ADMIN` 数据库角色。
- 不允许授权管理员查看审计日志。
- 不允许授权管理员审核评分或管理敏感词。
- 不改变普通评分、举报和评分修改规则。
- 不改变比赛锁定、积分榜或淘汰赛业务规则。

## 9. 验收标准

- 现有 `TEAM_MANAGER` 无需重新授权即可使用全部管理功能。
- 除审计、评分审核和敏感词外，授权管理员可以完成超级管理员可以完成的管理流程。
- 授权管理员看不到也访问不了审计和评分审核。
- `ADMIN` 权限不降低。
- `VIEWER` 仍不能进入任何管理页面或写接口。
- 前后端测试通过，生产部署后旧账号立即生效。
