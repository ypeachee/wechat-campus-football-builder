# 红黄牌禁赛系统设计

**日期：** 2026-10-28  
**状态：** 已确认，进入实现  
**规则：** 同赛事赛季累计 3 张黄牌停赛 1 场；直接红牌停赛 1 场；管理员可手动调整。

## 1. 目标

根据比赛中的红黄牌自动生成停赛，阻止停赛球员进入本队出场名单，并在后续比赛完赛后自动执行停赛场次。

## 2. 核心规则

- 黄牌只在同一 `season_id` 内累计。
- 每累计 3 张黄牌生成 1 场停赛；第 6、9 张黄牌继续生成新的 1 场停赛。
- 直接红牌生成 1 场停赛。
- 只有已完赛比赛中的红黄牌计入自动停赛。
- 自动停赛从产生红黄牌比赛的下一场本队比赛开始适用。
- 同一球员同时存在多项停赛时，每场只执行最早的一项。
- 球员在停赛执行场次中不得出现在首发或替补名单。
- 本队下一场有效比赛完赛且该球员未出场时，停赛场次减 1。
- 已执行过场次的自动停赛不允许通过编辑或删除来源红黄牌事件回滚。
- 比赛取消不执行停赛。
- 管理员和授权管理员可以手动创建、延长和解除停赛。
- 领队只能查看本队停赛信息，不能调整。

## 3. 数据模型

### 3.1 `player_suspension`

| 字段 | 说明 |
|---|---|
| player_id | 球员 |
| team_id | 所属球队 |
| season_id | 赛事赛季 |
| source_type | `YELLOW_ACCUMULATION` / `RED_CARD` / `MANUAL` |
| source_event_id | 自动停赛来源事件 |
| source_fixture_id | 自动停赛来源比赛，手动为空 |
| reason | 原因 |
| matches_total | 总停赛场次 |
| matches_served | 已执行场次 |
| status | `ACTIVE` / `SERVED` / `CANCELLED` |
| created_by | 操作者 |

唯一约束：`(source_type, source_event_id)`，手动停赛因事件为空可有多条。

### 3.2 `player_suspension_serving`

记录某停赛在哪场比赛执行，唯一约束 `(suspension_id, fixture_id)`，防止重复扣减。

## 4. 自动生成与重算

`SuspensionService.recalculateSeason(seasonId)`：

1. 按比赛时间、比赛 ID、事件 ID 排序读取已完赛比赛的红黄牌。
2. 每名球员独立累计黄牌，在第 3、6、9... 张黄牌对应事件上创建 1 场停赛。
3. 每张红牌创建 1 场停赛。
4. 使用来源事件唯一键保证重复执行不会产生重复停赛。
5. 未执行且来源已不再满足条件的事件，删除其自动停赛。
6. 已执行过场次的自动停赛保留，并阻止来源事件被修改或删除。

触发时机：

- 比赛完赛。
- 已完赛比赛的事件新增、修改或删除。

## 5. 自动执行

比赛完赛时：

- 对本场两个参赛球队查找 `ACTIVE` 停赛。
- 排除来源比赛就是本场的停赛。
- 如果球员在本场有出场记录，则本场不执行停赛。
- 如果球员没有出场，按创建时间选择最早的一项停赛，执行 1 场。
- 写入 `player_suspension_serving`；达到总场次后状态改为 `SERVED`。
- 取消比赛不触发执行。

## 6. 阵容和事件拦截

- 创建、编辑、批量替换出场前，检查球员是否存在适用于当前比赛的 `ACTIVE` 停赛。
- 停赛球员返回 `409 CONFLICT`，提示剩余停赛场次。
- 比赛事件录入同样拒绝停赛球员，红牌事件本身先写入，再生成后续停赛。
- 前端阵容和球员列表显示停赛状态，禁止勾选停赛球员。

## 7. API

- `GET /api/v1/manage/teams/{teamId}/suspensions?seasonId=`
- `GET /api/v1/manage/fixtures/{fixtureId}/suspensions`
- `POST /api/v1/manage/suspensions`
- `PUT /api/v1/manage/suspensions/{id}`

创建手动停赛：

```json
{ "playerId": 10, "matchesTotal": 2, "reason": "纪律处罚" }
```

调整：

```json
{ "matchesTotal": 3, "status": "ACTIVE" }
```

## 8. 小程序

- 球队管理页球员名单显示“停赛 X 场”。
- 授权管理员/超级管理员可以打开球队禁赛管理区域：
  - 选择球员
  - 设置停赛场次
  - 填写原因
  - 解除停赛
  - 延长 1 场
- 比赛阵容中停赛球员置灰并显示剩余场次，不能勾选。
- 比赛数据页显示本场停赛名单。

## 9. 测试

- 第 3 张黄牌生成停赛，第 6 张再生成一场。
- 红牌生成停赛。
- 重复重算不重复生成。
- 删除未执行来源事件会移除自动停赛。
- 删除已执行来源事件返回冲突。
- 停赛球员不能加入阵容。
- 下一场完赛且未出场时执行一场。
- 已出场记录不消耗停赛。
- 取消比赛不消耗。
- 手动创建、延长、解除。
- 领队只能查看本队停赛，不能调整。
- 公开页面和现有权限、评分、赛制测试不回归。

## 10. 验收标准

- 红黄牌能自动生成正确停赛。
- 停赛球员在阵容页不可选，后端也拒绝绕过。
- 后续比赛完赛后自动执行停赛。
- 管理员可以手动调整，领队不能。
